# One keyboard, two apps (Swoop <-> Kestrel)

Owner request 16 (2026-11-17): the Kestrel browser should use the Swoop keyboard's improvements, keep its own floating navigation panel, and the two must not diverge, learning included.
Owner request 17 (2026-11-17 evening): "The signing may remain public. ... Link kestrel to swoop keyboard so kestrel always uses swoop inside the browser and is an identical mirror to swoop at all times. Words and typing learned in kestrel should update swoop and vice versa. They should be one linked keyboard, but with the added functions inside kestrel browser."

## 1. The design in one paragraph
Kestrel types through the REAL Swoop keyboard whenever Swoop is installed. There is no copy of the keyboard inside Kestrel to keep in step: every Kestrel text box (address bar, Home box, find bar, the fields of a web page) takes Android's normal input path, Swoop is the chosen keyboard, so there is ONE learned memory, ONE dictionary and ONE set of settings (colours, layout, key height, glide trail, ...). Whatever is typed in Kestrel teaches Swoop and whatever Swoop learned elsewhere is used in Kestrel, because it is the same keyboard. No always-open channel between the two apps exists or is needed, so the PUBLIC signing key (decision R17a: it stays public) exposes nothing. What Kestrel adds on top ("added functions inside the browser"): the navigation panel's bar opens Swoop floating over the page; the address box tells Swoop what it is, so Swoop gives it a browser layout; private tabs make Swoop learn nothing; one hand-over of what Kestrel's own small keyboard learned before. Only when Swoop is NOT installed (or the Settings switch is off) the panel's own small keyboard opens (a pinned copy of the same engine, a separate memory, see section 4).

## 2. The whole interface between the two apps
| What | Direction | How |
| :- | :- | :- |
| "This box is the browser's address box" | Kestrel -> Swoop | `privateImeOptions = "app.kestrel.omnibox=1"` on the address box and the Home box. Swoop reads it in `FieldInfos` and makes the field kind `OMNIBOX`: the URL keys (slash, .com, full stop) and the Go key, but words are tapped as composing text, glide works, guesses show, everything is learned; NO automatic capital, space after punctuation, double-space full stop, typo fix, capital I, emoji suggestion or translate (an address must stay an address). |
| "Learn nothing from this box" (private tab) | Kestrel -> Swoop | the STANDARD flag `IME_FLAG_NO_PERSONALIZED_LEARNING` on the address box, the Home box and (new, `KestrelGeckoView.onCreateInputConnection`) the fields of a page in a private tab. Swoop already honours it everywhere. |
| "Float over the page" / "dock" | Kestrel -> Swoop | the private command `app.swoop.keyboard.FLOAT` / `DOCK` (`InputMethodManager.sendAppPrivateCommand`), delivered by Android only from the app whose box is being edited and only to the current keyboard; it carries no data. |
| "Make Swoop the keyboard" | Kestrel -> person | Swoop installed but not chosen: the panel's keyboard button opens Android's keyboard picker (or the keyboard settings when Swoop is not switched on yet). An app cannot switch keyboards silently. |
| "What Kestrel's own keyboard learned before" | Kestrel -> Swoop, once, on a tap | an EXPLICIT intent `ACTION_SEND` with the export file (content URI + read grant) to `app.swoop.keyboard/.ReceiveLearnedActivity` (debug build: `app.swoop.keyboard.debug`). That screen has no intent filter (never in a share sheet), reads at most the export size limit, accepts only a learning export (magic header), shows what is in it and adds nothing without a tap on Import. It is the only exported component besides the keyboard service and the launcher (AndroidManifest comment). |
| package visibility | Kestrel manifest | `<queries>` for `app.swoop.keyboard` and `app.swoop.keyboard.debug` (Android 11 and later hide other packages otherwise). |

## 3. Why there is no live data channel (and the public signing key is harmless)
A ContentProvider or bound service between the apps would have to be protected by a signature permission, but BOTH apps are signed with a PUBLIC dev key (decision R17a), so any app anyone signs with that key could read the owner's typing history. The design above needs no such channel: typing in Kestrel already goes into Swoop through Android's own input path. The only thing that crosses is the one-time, explicit, confirmed hand-over of the OLD file (section 2). The trade-off the owner accepted earlier stays what it was: anyone could sign an APK that updates an installed Swoop or Kestrel, so install them only from the repositories' Releases.

## 4. The panel's own keyboard: the SAME engine as Swoop, kept identical on purpose
When Swoop is not installed (or the Swoop link is switched off in Kestrel's Settings) the panel opens its own small keyboard. It is not a look-alike: it runs Swoop's engine.
* **Engine, word list, shape network.** The glide / typing engine (`app.kestrel.core.input`: layout, decoder, personal model, suggester, dictionary, emoji, the trained shape network code, the learning rules) is DEVELOPED in `tjshea90/Keyboard` (`core/`). The Kestrel repo holds a vendored copy of `core/src/{main,test}/kotlin/app/kestrel/core/input/**`, of the word list `geckoapp/src/main/assets/glide/en.klx`, of the trained shape network `swipe_encoder.bin` (R30, with its licence) and of the network's parity reference (`core/src/test/resources/swipe_reference.bin`). Never edit them in Kestrel. `MiniNav.startGlideEngine` switches the network on exactly like Swoop does (`shapeModel = true`).
* **The pin.** `KEYBOARD_PIN` names the Keyboard commit and the sha256 of the engine sources, of the word list and of the shape network. `bash tools/check-keyboard-core.sh` fails when any of them differs from the pin, and `tools/test_handoff.sh` runs it. The Keyboard repo prints the same engine fingerprint with `bash tools/core-input-hash.sh`.
* **One learning rule (owner R40-6, 2026-11-28).** What a glide that stays in the text teaches the memory is ONE function, `GlideLearning.confirm` (core): Swoop's `GlideSession` and the panel's `MiniNav.confirmGlide` both call it. A glide that merely stayed is a light lesson when its word is rare (so "ave", "access", "yo" and "Maggie" cannot feed themselves), a word the person picked counts three times and takes back what the wrong first guess had earned, a word typed in its place after a deleted glide counts three times. Until 2026-11-28 the panel taught every kept glide at full weight: the loop that R29 / R33 had closed in Swoop only.
* **Keeping it identical, always.** After ANY Swoop change under `core/.../input` (or the word list or the network), once it is committed, the Swoop session runs ONE command from its own repo: `bash tools/sync-browser.sh` (`--status` only reports; `--test` also runs this repo's JVM suites). It brings the other Kestrel branches into the session's own Kestrel branch, runs `tools/sync-keyboard-core.sh` here (engine, word list, network, reference), checks the pin and commits + pushes THAT branch (never main, never another session's branch, never a release). `tools/resume.sh` of the Keyboard repo prints "Browser link: ... BEHIND" at every session start while the newest Kestrel branch carries an older engine, and `ship.sh` names the command in its next-step card. This repo's own `tools/sync.sh` then brings that branch into every other Kestrel session at its next checkpoint, and the next Kestrel release carries it. Update by hand: `bash tools/sync-keyboard-core.sh <Keyboard checkout>` (it refuses an uncommitted checkout), run `:core:test :app:testDebugUnitTest`, commit.
* **What is NOT shared (honest).** The screen and the text editing around the engine are Kestrel's own: the panel's keys, `MiniKeyboardModel` and the edits in the address bar and in page fields. The rules that live in Swoop's presenter are not in the panel: the automatic fix on a space (names and capitals-only words are never fixed), the fix of the word before, the strip's replace-not-append rules, the recovery when an app ends the composing word. The panel has no automatic fix and no fix-the-word-before, so it cannot make those mistakes. Moving the panel onto `InputController` + `GlideSession` + `TypingLearner` (as Swoop is built) would make it identical in behaviour too; it is a larger change and the recommended next step.
* **The learned memory** of the panel is its own file in Kestrel's storage (`glide_personal.txt`, format `KESTREL-KEYBOARD-LEARNING`); Export in one app and Import in the other moves it, and the hand-over of section 2 does it in one tap. When Swoop is the chosen keyboard (the normal case) nothing is copied at all: typing in Kestrel feeds Swoop's one memory.

## 5. Tested here / not proven on a device
* Unit-tested: `KeyboardPresenterTest`, `FieldInfosTest`, `TypingOptionsTest`, `ImeLayoutTest` (omnibox), `ReceiveLearnedActivityTest` (hand-over screen), `KeysServiceTest` (private command); Kestrel `SwoopLinkTest`, `SwoopInstalledTest`, `MiniNavTest`, `HandOverProviderTest`.
* **Run on an emulator** (2026-11-17, `.github/workflows/daily-sim.yml`, `tools/sim/`; an Android 10 tablet-shaped KVM emulator, 600 x 1024 at 170 dpi, 2 GB, low-RAM flag; Swoop chosen as THE keyboard; Kestrel G built from the Browser branch with the real Firefox engine; the link at full speed, the way the owner mostly browses):
  * Swoop shows in all six kinds of web-page text box (text, search, textarea, contenteditable, url, e-mail): 7 of 7 tapped phrases exact (capital, digit, apostrophe, comma, question mark through ?123 / Shift), 20 of 20 glided words right in each kind, also with a thumb landing 0.2 key off the centre; the word is on the page within about 0.2 s of the lift (the page's own report is the proof, not a screenshot).
  * Autocorrect inside Gecko: teh -> the, dont -> don't, recieve -> receive, im -> I'm; one Backspace gives the typed word back.
  * Kestrel's address box: Swoop's debug line reads `startInput kind=OMNIBOX ... omnibox=true`, the browser keys (slash, full stop, Go) are there; example.com loads in 1.0 s and en.wikipedia.org in 3.3 s.
  * A private tab: `noLearn=true`; a normal tab: `noLearn=false`.
  * Memory: Swoop 40 to 44 MB PSS (debug build), Kestrel 238 to 257 MB with a page open.
  * 10 real sites loaded in Kestrel at full speed: first paint 0.2 to 2.8 s, load finished 0.25 to 5.9 s (apnews.com, with 54 requests blocked, is the slowest).
  * A 10 second film pressed to play: Kestrel's own player started inside the page, first picture after 1.2 s, 0 stalls, 5 dropped frames of about 300 (a software decoder on the emulator, not the tablet's hardware).
  * The emulator's own graphics (SwiftShader) gave up twice, on one particular web page and on a 1080p film (Android's system_server watchdog restart loop): an emulator limit, not shown to be a Kestrel defect; those two were taken out of the test lists.
  * A Google results page asked Kestrel for the location: Kestrel showed its own Block / Allow question (the simulation taps Block).
  * Emulator numbers are NOT the tablet's (x86_64, software GPU, fast CPU): they are relative to other runs of the same kind.
* NOT proven on a real tablet or phone: the panel -> Swoop floating round trip, the keyboard picker flow, the hand-over of the old learned file, Swoop's speed and memory in GeckoView fields on the MT8168B, real-thumb accuracy.

## 6. What would make the panel's memory live-shared with Swoop (needs the owner's decision, NOT done)
Owner R40-6 asks for "everything it learned" to be identical at all times. With Swoop chosen it already is (section 1: one keyboard, one memory). For the panel's own copy (Swoop not chosen) the only live way is a read-only channel: Swoop would answer the panel's request with its current learned export, the panel would load it as its personal memory when its keyboard opens and keep what it learns in the session only (or hand it back with section 2). It needs a new EXPORTED component in Swoop's manifest (a ContentProvider), which reverses the R17 decision "no live channel": both apps are signed with the PUBLIC dev key, so a signature permission protects nothing; the protection would be (1) an allow-list of the Kestrel package names checked on every call (a package name cannot be taken while the real Kestrel is installed), (2) a switch in Swoop's Settings, off until turned on, (3) a size-safe stream (a file descriptor, not a Binder bundle). The remaining risk is the one the owner already accepted for updates: an APK signed with the public key that replaces Kestrel. Not built because it changes Swoop's manifest and an earlier decision; say yes and it is one session of work with tests (Robolectric on both sides; the round trip on a device is NOT provable here).
