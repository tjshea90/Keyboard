# How the Kestrel browser takes text input today (read-only survey of tjshea90/Browser, 2026-11-17, for TASKS R17b)

Paths below are in the Browser repo: APP = app/src/main/kotlin/app/kestrel/browser, GECKO = geckoapp/src/main/kotlin/app/kestrel/browser, MF = geckoapp/src/main/AndroidManifest.xml.

* EVERY Kestrel EditText and EVERY GeckoView page field already uses the SYSTEM keyboard (Swoop when it is the chosen keyboard). Only the navigation panel's bar has an own keyboard (the "mini keyboard", ui/MiniNav.kt).
* Address bar = `BottomDock.urlField` (ui/BottomDock.kt:81), plain EditText, inputType TEXT|URI (:106), imeOptions GO|NO_EXTRACT_UI plus NO_PERSONALIZED_LEARNING in a private tab (:205). `privateImeOptions` is set nowhere. Home box: ui/HomeView.kt:26,55,123 (same). Find bar: ui/Panels.kt:167,183-184 (NO_SUGGESTIONS, SEARCH; no private flag). Only Settings text field: pairing dialog ui/SettingsView.kt:277. Dialog fields: BrowserActivity.kt:3433, 3448-3449.
* Nothing suppresses the system keyboard (no showSoftInputOnFocus / setRawInputType / ALWAYS_HIDDEN; manifest adjustResize). BrowserActivity shows it in focusUrlBar (:2232) and hides it in hideKeyboard (:2238).
* Page fields: the mini keyboard types into them through the GeckoSession's InputConnection (PageFieldInput.kt:66, commitText / deleteSurroundingText / DEL, ENTER, DPAD key events :83-108; no JS). The system keyboard is held back ONLY while the mini one is open (showSoftInput / restartInput swallowed, PageFieldInput.kt:36-46, wired BrowserActivity.kt:1384-1386, hideKeyboard :180). Field focus never opens the mini keyboard (MiniNav.kt:296 only re-syncs).
* The ONE decision point: `MiniNav.openKeyboard` (MiniNav.kt:263-278) calls `navSwoop(true)` first, else `navPageField()` (BrowserActivity.kt:174-179). Its callers: the panel bar tap (MiniNav.kt:866) and ACTION_UP (:935). `BrowserActivity.navSwoop` (BrowserActivity.kt:185-195) returns false when the pref is off or Swoop is not the CHOSEN keyboard (then the mini keys open); otherwise it focuses the GeckoView and shows the keyboard (page field) or calls focusUrlBar (dock / Home) and sends FLOAT at 300 / 1100 ms. DOCK is never sent. `swoopUp` (MiniNav) goes stale if Swoop closes itself (cleared only at :206 and :281).
* Own learned data: filesDir/glide_personal.txt (BrowserActivity.kt:164-172, tmp + rename; PersonalModel text) written by the vendored core GlideTyping (core/.../glide/GlideSupport.kt:234,496-512), created at MiniNav.kt:365 and saved on close (:285); prefs "kestrel": glide_bx, glide_by, glide_words (data/Prefs.kt:13,161,163). Export = "Kestrel keyboard learning yyyy-MM-dd.txt" in Downloads, header KESTREL-KEYBOARD-LEARNING 1 (ui/KeyboardFlow.kt:52-69,72-80,124; MiniNav.kt:326-357; BrowserActivity.kt:3374); Settings rows ui/SettingsView.kt:79-81 (handlers BrowserActivity.kt:2588-2598).
* Private tabs: address bar and Home box set NO_PERSONALIZED_LEARNING (BottomDock.kt:205, HomeView.kt:123); the find bar and the JS prompt / auth fields do not. PAGE fields: Kestrel sets nothing (KestrelGeckoView has no onCreateInputConnection; sessions use usePrivateMode, BrowserActivity.kt:1367); PageFieldInput.kt:76 only ASSUMES GeckoView adds the flag: unproven on a device.
* Swoop detection (app/.../SwoopLink.kt): isSwoopId (:21), isChosen (:28, default_input_method), isEnabled (:31, no callers), sendFloat (:34). No "installed" check and no <queries> entry (MF:28-36: needed for package visibility on Android 11+). Prefs.swoopKeyboard default true (data/Prefs.kt:154-155), one Settings row ui/SettingsView.kt:139.
* Emulator tools: tools/emu/soak.py (open_url = `am start -a VIEW -d`, :61), glide_emu.py (raw touches), firstpage_emu.py; tools/sitelab/fieldlab.py (logs page-field input). Debug intents `--es kestrel_debug dump|privtab|closetabs` (BrowserActivity.kt:900-948). Logcat tag KestrelHealth (debug builds): `page loaded host= paint= done= blocked= ok=` (diag/PageTimes.kt:60), `page error` (BrowserActivity.kt:2905), `ui STALL` (diag/Health.kt:107); parser at soak.py:496. Package app.kestrel.browser.gecko.debug, activity app.kestrel.browser.MainActivity; build `./gradlew :geckoapp:assembleDebug -PgeckoAbi=x86_64`.

## Consequence for "Kestrel always uses Swoop" (R17b)
Little has to change: gate navSwoop on "Swoop installed" instead of "pref + chosen" (installed but not chosen -> the Android keyboard picker, since an app cannot switch keyboards silently), add isInstalled + <queries>, tell Swoop about the address box (privateImeOptions app.kestrel.omnibox=1), make private page fields carry NO_PERSONALIZED_LEARNING (KestrelGeckoView.onCreateInputConnection), mini keys only as the fallback when Swoop is not installed, one explicit hand-over of what the mini keyboard learned (FileProvider + explicit intent to Swoop's ReceiveLearnedActivity).
